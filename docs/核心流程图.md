# 核心流程图

## 文档用途

本文把苍穹外卖里最重要的三条链路画成流程图，方便面试时讲清楚“下单、支付、通知、状态流转”这几个核心问题。内容基于当前源码；未实现的部分会在图中或图后注明。

## 参考源码

- 订单业务：`sky-server/src/main/java/com/sky/service/impl/OrderServiceImpl.java`
- 支付回调：`sky-server/src/main/java/com/sky/controller/nofity/PayNotifyController.java`
- 微信支付工具：`sky-common/src/main/java/com/sky/utils/WeChatPayUtil.java`
- WebSocket：`sky-server/src/main/java/com/sky/websocket/WebSocketServer.java`
- 定时任务：`sky-server/src/main/java/com/sky/task/OrderTask.java`
- 订单实体：`sky-pojo/src/main/java/com/sky/entity/Orders.java`

## 一、信息流图

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户端
    participant OC as OrderController
    participant OS as OrderService
    participant OM as OrderMapper
    participant OD as OrderDetailMapper
    participant WP as WeChatPayUtil
    participant WX as 微信支付平台
    participant PN as PayNotifyController
    participant WS as WebSocketServer
    participant M as 管理端浏览器

    U->>OC: 提交订单 / 发起支付
    OC->>OS: submitOrder() / payment()
    OS->>OM: 校验地址、写入 orders
    OS->>OD: 写入 order_detail
    OS-->>U: 返回订单信息 / 支付参数

    alt 真实统一下单（源码已注释）
        OS->>WP: pay(orderNumber,total,description,openid)
        WP->>WX: JSAPI 下单
        WX-->>WP: prepay_id + 支付参数
        WP-->>OS: timeStamp/nonceStr/package/paySign
    else 当前仓库运行逻辑
        OS->>OS: 返回简化的 OrderPaymentVO
    end

    OS->>OM: 更新为待接单/已支付
    OS->>WS: 推送来单提醒
    WS-->>M: 商家端收到新订单提醒

    WX-->>PN: 支付成功回调
    PN->>PN: 解密通知数据
    PN->>OS: paySuccess(outTradeNo)
    OS->>OM: 更新订单状态和支付状态
    PN-->>WX: SUCCESS

    M->>OC: 接单 / 拒单 / 配送 / 完成
    OC->>OS: confirm/rejection/delivery/complete
    OS->>OM: 状态流转更新

    Note over U,WS: 当前源码没有看到用户端 WebSocket 主动推送，用户通常通过刷新/查询订单状态感知变化
```

## 四、面试关注点

- 信息流里最关键的是“订单写库、支付回调、状态推进、WebSocket 通知”四步。
- 资金流里要主动说明：当前仓库能看到退款调用，但没有完整退款闭环。
- 状态机里要分清 `status` 和 `pay_status`，不要把“已支付”和“已接单”混成一个状态。
- 当前用户端没有明确看到主动推送，别硬说“用户也收到了 WebSocket 通知”。
